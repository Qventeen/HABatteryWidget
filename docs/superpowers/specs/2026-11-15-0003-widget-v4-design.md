# Widget v4 — design

- **Date:** 2026-11-15
- **Status:** written; waiting for the owner's review. No code before approval.
- **Set:** `0003`. The spec lives on `develop`; the code goes on branch
  `0003-widget` (from `develop`).
- **Builds on:** spec 0001 (`2026-11-14-0001-clean-rewrite-design.md`),
  spec 0002 (`2026-11-15-0002-corrections-design.md`, merged in `676a1df`)
  and widget design **v4** (`docs/design/`, merged in `d89f4f1`).

## 1. Intent

Build the home-screen widget as designed in v4: SOC ring, two big pack
values, small cell and temperature pills, a top row with time left, the
balancing icon, the update time or a sync error, the auto-refresh toggle
and manual refresh. The app's overview card shows the same layout. The
user picks what the widget shows (kWh or Ah, current or power) and the
font sizes. Spec 0002 already reads every value this needs, except the
optional total-capacity sensor added here.

## 2. Goals, non-goals, anti-goals

**Goals**

- The v4 layout, its states and its colour rules (`docs/design/README.md`
  is the visual reference; this spec decides how to build it).
- Display choices and font-size settings for the whole app.
- The same layout in the app's overview card.
- An auto-refresh toggle on the widget.
- Time left in days from 24 h; temperature warning colours; the one-sensor
  temperature layout; the total-capacity sensor.

**Non-goals**

- Live values (WebSocket) — the owner keeps REST (2026-11-15).
- Per-widget settings, other widget layouts (e.g. 4×1), user-set
  temperature limits, cell count and cell type.
- Rounded pills on Android 8–11 (approach D).
- Any marking of old data beyond today's update-time text (it already
  shows the date for older readings).

**Anti-goals** (a failure even if it works)

- Network calls in `provideGlance` (0001 rule: the widget renders only
  from the cache and the settings).
- The layout jumps between states that have data (normal, refreshing,
  error, a missing value): the same elements stay in the same places.
- Text that does not fit at any allowed font-size setting.
- The widget or the app writes anything to Home Assistant.

## 3. Owner decisions (2026-11-15)

1. **Size:** starts at 4×2 cells; can be made bigger and the same layout
   stretches; no other layouts. Refined after the builder check: the
   minimum size is 85 % of the design (306 × 153 dp), so the launcher picks
   4×2 on most phones and 5×2 on dense 5-column grids (where 4×2 is only
   about 276 dp wide).
2. **States:** with data, the layout stays: the sync error replaces the
   update time, ↻ dims while refreshing, a missing value shows "—". With
   no data at all (setup needed / no data yet): one centered message and
   an "Open app" button.
3. **Auto toggle on the widget:** turning it on with no interval set uses
   15 min; a set interval is kept.
4. **Long time left:** "45 min", "17 h 16 min", from 24 h "2 d 7 h".
5. **Temperature colours:** fixed limits, no settings. Battery sensors:
   amber below 5 °C or above 45 °C, red at 0 °C or below or above 55 °C.
   MOSFET: amber above 65 °C, red above 80 °C.
6. **Temperature pills:** one battery sensor → one pill without an arrow
   (4 pills); two or more → highest ↑ and lowest ↓ (5 pills); MOSFET last.
7. **App overview card:** the same look as the widget, drawn in Compose.
8. **Full capacity:** optional entity `sensor.<p>_total_battery_capacity`
   (Fill sets it); when empty or unavailable, the hand-typed capacity.
9. From 0002: display choices are app-wide ("kWh or Ah left" under SOC,
   "current or power" in the second big pill); data stays REST.

## 4. Approaches (Claude's calls; the owner handed over the how)

**A. One model for widget and app card**

- **A1 (chosen):** a pure-Kotlin `WidgetModel` in `domain/` decides what
  shows: which pills, values, levels, state. Glance and Compose only draw
  it. Owner decision 7 means two drawings; this keeps the rules in one
  tested place.
- A2: each layout reads the overview and decides on its own. Cost: every
  rule twice, and they drift.

**B. The SOC ring**

- **B1 (chosen):** a white arc bitmap (the filled part, drawn per SOC) on
  top of a vector circle (the track); both are tinted with day/night
  colour providers. On Android 12+ a theme switch needs no redraw, and the
  bitmap is small (alpha only). On Android 8–11 day/night colours (and the
  system font scale of E1) are fixed when the widget is drawn, and change
  at the next redraw (a sync or a settings change) — the same limit as
  today's widget. *(Builder check; Claude's call: accepted, no extra
  hook.)*
- B2: a full-colour bitmap per theme: a redraw on every theme switch.
- B3: keep `LinearProgressIndicator` (0001 call 12): not the design.

**C. Sizes**

- **C1 (chosen):** one layout. A scale factor
  `s = min(1, width / 360 dp, height / 180 dp)` from the widget's real size
  (`SizeMode.Exact`) multiplies every fixed size (padding, ring, pill
  heights, gaps, fonts), except the two buttons: they keep their 44 dp
  touch area and 36 dp circle. With the minimum size of 5.1, `s` is at
  least 0.85 (small text ≥ 8.9 sp at the default size). Bigger than
  360 × 180: fixed sizes stay at 1×; the extra room goes to the flexible
  parts (big pills, spaces). If a launcher still gives less, the layout
  keeps fitting: everything but the buttons shrinks together, and the top
  row needs only 88 dp + 156 dp × `s` of its 336 dp × `s`.
- C2: size tiers (today's code): more layouts than the owner wants.

**D. Rounded corners on Android 8–11**

- **D1 (chosen):** Glance `cornerRadius` (Android 12+); on Android 8–11
  pills and card are square. `minSdk` 26 stays.
- D2: rounded background drawables for old versions: more drawables and
  tinting code for a small share of phones.

**E. Font sizes and the system font scale**

- **E1 (chosen):** the effective size = setting × system font scale,
  capped at the group's maximum (5.3). Large system text is respected up to
  the size the layout holds.
- E2: ignore the system font scale: worse for users who need large text.

**F. Widget settings in the app**

- **F1 (chosen):** a new foldable section "Widget" (same pattern as 0002):
  the two display choices, the five font sizes, a reset. Changes save at
  once (like the notification switch) and redraw the widget.
- F2: a separate screen: needs navigation (0002 approach C).

## 5. Design

### 5.1 Widget size (`res/xml/battery_widget_info.xml`)

- `minWidth` 306dp, `minHeight` 153dp (85 % of the 360 × 180 design);
  `minResizeWidth` 306dp, `minResizeHeight` 153dp (never smaller);
  `maxResizeWidth` / `maxResizeHeight` 460dp (as today); `resizeMode`
  horizontal|vertical.
- **No `targetCellWidth` / `targetCellHeight`:** a fixed 4×2 target would
  place the widget at about 276 dp on 5-column launchers, below the
  minimum. Without it, the launcher computes the cells from the minimum
  size: 4×2 on most phones, 5×2 on dense grids (owner, 2026-11-15).
- `previewLayout` is redrawn as the v4 normal state (static sample values).

### 5.2 The model (`domain/WidgetModel.kt`, pure Kotlin)

`WidgetModel.build(overview: BatteryOverview, settings: Settings): WidgetModel`

- `WidgetModel.Empty(kind: SETUP | NO_DATA, error: SyncError?)` when setup
  is needed or there is no reading.
- `WidgetModel.Data` otherwise, with:

| Field | Rule |
|---|---|
| `socPercent`, `ringFraction`, `ringLevel` | rounded SOC; SOC / 100 clamped 0–1; level green ≥ 25 %, amber < 25 %, red < 15 % (today's `WidgetLevels.charge`) |
| `underSoc` | kind KWH or AH (setting); value = Ah left × V / 1000 or Ah left; null when an input is missing |
| `voltage` | total voltage |
| `main` | kind CURRENT or POWER (setting); value = \|current\| or \|power\|; null when missing |
| `direction` | UP when current > 0.1 A, DOWN when < −0.1 A, NONE otherwise or when current is missing |
| `mainLevel` | OK (green) for UP, WARN (amber) for DOWN, IDLE (grey) for NONE — from the current, also when the state is FULL |
| `timeLeft` | `BatteryMath.timeRemaining` (0002), with full capacity from 5.6; null when FULL |
| `balancing` | from the reading |
| `updatedAtMillis` | from the reading |
| `error` | `overview.error` |
| `refreshing`, `autoRefresh` | from the overview and the settings |
| `averageCellVoltage` | from the reading |
| `deltaMv`, `deltaLevel` | `BatteryMath.deltaMv`; today's delta levels |
| `temperatures` | by the **configured** list size (stable layout): 0 → `None` (no battery pill, 3 pills); 1 → `One(value, level)`; ≥ 2 → `MaxMin(max, maxLevel, min, minLevel)` over the values that exist |
| `mosfet`, `mosfetLevel` | from the reading; MOSFET levels (decision 5) |

A missing value stays in the model as null; the drawing shows "—" (and the
plain level). Temperature levels: `WidgetLevels.battery(c)` and
`WidgetLevels.mosfet(c)` with the limits of decision 5.

### 5.3 Settings (`domain/model/Settings.kt`)

- `display: DisplaySettings(underSoc: UnderSoc = KWH, mainValue: MainValue = CURRENT)`.
- `fontSizes: FontSizes` in sp, with default and allowed range (checked on
  the v4 design at the maximum of every group; see 5.4):

| Group | Default | Range |
|---|---|---|
| `soc` (SOC number) | 40 | 32–42 |
| `underSoc` (kWh / Ah) | 12 | 10–12 |
| `main` (voltage, current / power) | 22 | 18–24 |
| `cell` (cell pill values) | 14 | 12–15 |
| `small` (SOC label, time left, update time, error) | 10.5 | 9–12 |

  Steps: 1 sp, `small` 0.5 sp. Stored values outside the range are clamped
  when read.
- `EntitySettings.totalCapacity: String = ""` (new); Fill sets
  `sensor.<p>_total_battery_capacity`; label "Total capacity (Ah)"; the id
  check is the existing one.

### 5.4 Widget layout (Glance)

The v4 README gives every size at 1×; multiply by `s` (approach C1).

- **Card:** 12 dp padding, 24 dp corners, background day/night card colour.
  A tap on the card opens the app (as today).
- **Top row (44 dp):** hourglass + time left (`Formatters.duration`, "—"
  when null); balancing icon (green on, grey off; content description);
  then either the update time (`Formatters.updatedAt`) or, when `error` is
  set, a red ⚠ icon + `Formatters.error(error)` in one line (`maxLines = 1`;
  a long text is cut); the auto-refresh toggle (36 dp circle in a 44 dp
  touch area; green tonal on, grey with a slash off; content description
  on/off); ↻ (dimmed and described "Refreshing…" while `refreshing`).
- **Body** (4 dp below the top row): ring 104 dp (approach B1) with "SOC",
  the number and the `underSoc` line inside; the middle column with two big
  pills (voltage; main value with the direction arrow; 6 dp gap); the right
  column, 90 dp wide, 19 dp pills spread over the height: average cell,
  delta, the temperature pill(s), MOSFET last. Temperature pills: 13 dp
  icon, 10 dp arrow slot (empty without an arrow), 3 dp space, value.
- **Fonts:** the five groups of 5.3, effective size = setting × system font
  scale, capped at the group's maximum (approach E1), then × `s`.
- **Empty model:** the card shows a battery icon, the title
  ("Set up in the app" or "No data from Home Assistant"), the error text
  for NO_DATA when there is one, and an "Open app" button.
- **Content descriptions** on every icon-only element: direction, balancing,
  sync error, battery temperature (or highest / lowest), MOSFET, both
  buttons, the ring ("State of charge N percent").

Checked on the v4 design (Chromium render, 1 px = 1 dp): no overflow with
every group at its maximum; the line under SOC keeps ≥ 0.3 dp from the ring
at SOC 42 / 12 and about 3 dp at the defaults; "↑ 4.38 kW", "314.0 Ah"
and "↓ 125.5 A" fit.

### 5.5 Ring bitmap

- `widget/RingBitmap.kt`: `fun arc(fraction: Float, sizePx: Int, strokePx: Float): Bitmap`
  — an `ALPHA_8` bitmap with a round-capped arc from 12 o'clock clockwise.
  Cached per (fraction in whole percent, size).
- The track is a vector drawable (a full circle, same stroke), tinted with
  the track colour; the arc is tinted with the ring-level colour; both via
  `ColorFilter.tint` with day/night colour providers.
- Size in px = 104 dp × `s` × density.

### 5.6 Full capacity

- `TemplateBuilder` adds key `capacity` (`states(id) | float(none)`);
  `TemplateResponse` maps it to `BatteryReading.totalCapacityAh: Double?`
  (non-finite → null).
- Time to full and the SOC fallback use `reading.totalCapacityAh` when it
  is present and > 0, else `settings.capacityAh`.
- The capacity section hint: "Used when the total capacity sensor is empty
  or unavailable."

### 5.7 Auto-refresh toggle action

`widget/ToggleAutoRefreshAction.kt` (`ActionCallback`):

1. Read the settings. New `auto` = the opposite of the current one.
2. Turning on with `intervalMinutes == null` → set 15.
3. Save; `scheduler.apply(settings, settingsChanged = true)`; when it was
   turned on, also `syncNow()`; redraw all widgets.

The app's Refresh section follows the change: its drafts are keyed on the
stored refresh settings (`RefreshSection.kt`, checked), so it shows the
new state and the 15 min.

### 5.8 Time format

`Formatters.duration`: under 1 h "45 min"; under 24 h hours and minutes
(as today); from 24 h days and hours ("2 d 7 h"), localized with
`MeasureFormat` (DAY, HOUR) like today's code. Used by the widget and the
app card.

### 5.9 App overview card (Compose)

- Draws the same `WidgetModel`: the ring with `Canvas.drawArc`, pills as
  rounded surfaces, the same colours (from the green theme's tokens), the
  same font settings, scaled by the card's own width:
  `s = min(1, width / 360 dp)` (narrow phones, landscape, split screen).
  *(Builder check; Claude's call.)*
- The empty model shows the message only (no "Open app" inside the app).
- The 0002 temporary list lines and the old status text are removed.

### 5.10 Widget settings section

- Foldable section "Widget" after Capacity: "Under SOC": kWh / Ah
  (segmented buttons); "Second value": Current / Power; five sliders with
  the value in sp (ranges of 5.3); "Reset sizes". Summary when folded,
  e.g. "kWh · current".
- Each change saves at once and redraws the widgets (approach F1).

### 5.11 Removed

`WidgetLayoutSpec` and the density tiers, the status line, the refresh-mode
text, `LinearProgressIndicator`, `WidgetDimens` tier values (replaced by
the 1× sizes × `s`), the 0002 overview list lines, and every string no
longer used (both languages).

### 5.12 Strings, stored data, tools

- New texts in `values/` and `values-uk/`: section title and labels, the
  choice names, "Reset sizes", "Total capacity (Ah)", the empty titles,
  "Open app", content descriptions, the new hint.
- Stored data: `display`, `fontSizes`, `totalCapacity` and
  `totalCapacityAh` have defaults; old data loads; `schemaVersion` stays 1;
  `StoredJsonV1Test` pins the new format.
- `tools/mock_ha.py` gets `--capacity`.

## 6. Tests

- **Domain:** `WidgetModelTest` — Empty (setup, no data with and without an
  error); Data with each display choice; direction and `mainLevel` at
  ±0.1 A and when FULL; `timeLeft` null when FULL; temperatures for list
  sizes 0, 1, 2 and with missing values; every temperature level edge
  (5 / 45 / 0 / 55 °C, 65 / 80 °C); null inputs give null values. Capacity
  precedence in `BatteryMathTest`; `EntityFill` sets the capacity id;
  settings range clamping.
- **Data:** `TemplateBuilder` / `TemplateResponse` with `capacity`.
- **Format:** `duration` at 59 min, 23 h 59 min, 24 h, 2 d 7 h (en and uk).
- **Widget (Glance unit tests, `runGlanceAppWidgetUnitTest`):** each state
  (normal, refreshing, error, missing value, empty setup, empty no-data);
  1 vs 2+ temperature pills; kWh/Ah and current/power texts; content
  descriptions; no network in `provideGlance` (existing guard).
- **Action:** toggle on with no interval → 15 and a sync; toggle off.
- **UI:** `MainViewModel` saves display choices and font sizes; androidTest
  for the Widget section and the overview card (renders the model).
- **Done gate:** `bash ./gradlew lint testDebugUnitTest assembleRelease`;
  instrumented tests on the `Pixel_8_API_35` AVD (it exists and passed in
  0002; on `Pixel_8_API_37` the test runner fails for an environment reason,
  see 0002). No AVD below Android 12 exists, so the square-corner fallback
  (approach D1) is checked only by reading the code.
- **Manual:** emulator with `tools/mock_ha.py`; screenshots of the widget
  (normal, error, no data; light and dark) and the app card for the owner.
