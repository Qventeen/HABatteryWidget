# Temperatures (0004) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans (inline). Steps use checkbox (`- [ ]`) syntax.

**Goal:** Show one battery temperature pill (average of the configured sensors, coloured by the worst sensor) plus MOSFET, and make Fill find every `sensor.<p>_temperature_sensor_N` in Home Assistant.

**Architecture:** `WidgetModel` (domain) computes the average and the worst level; Glance and the Compose card only draw it. A new port method `BatterySource.listTemperatureSensors` sends one extra `POST /api/template`; `MainViewModel` runs it for Fill and returns the result to the Entities section, which updates its draft.

**Spec:** `docs/superpowers/specs/2026-11-15-0004-temperatures-design.md` (section numbers below refer to it).

## Builder calls (spec 7)

1. **Template:** `{{ states.sensor | map(attribute='entity_id') | select('match', 'sensor[.]<p>_temperature_sensor_[0-9]+$') | list | to_json }}`. `[.]` avoids backslash escapes; the prefix is limited to `[a-z0-9_]`.
2. **Model field:** `Temperatures.Battery` also carries `sensors: Int`, so the pill can say "Average battery temperature" with two or more sensors.
3. **Content description:** the icon description only (as the other pills): "Battery temperature" or "Average battery temperature". No value, no level.
4. **Fill result:** `MainViewModel.findTemperatureSensors(prefix, stillCurrent)` returns a sealed `SensorSearch` (`Skipped`, `Found`, `NoneFound`, `Failed`, `Superseded`); the section applies it to its draft and shows the note.
5. **Progress:** the Fill button is disabled and a small progress ring sits in the Entities section while the request runs. The notes sit under the temperature list.
6. **Mock:** `tools/mock_ha.py` gets `--prefix` (default `bps_bms`) and answers the listing template for that prefix.
