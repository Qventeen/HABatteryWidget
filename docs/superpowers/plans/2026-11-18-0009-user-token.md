# User Token Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let the app read Home Assistant with a non-admin ("User") token through `GET /api/states/<id>`, keep the admin template path as it is, and keep one saved token per type.

**Architecture:** `ConnectionSettings` gets `tokenType`. `TokenStore` keeps one encrypted slot per type. A router `TokenTypeSource` sends each `BatterySource` call to the existing `HomeAssistantSource` (ADMIN) or a new `StatesSource` (USER). Both use one shared HTTP helper, `HaHttp`. The Access token section gets Admin | User buttons, a Remove button and a hint.

**Tech Stack:** Kotlin, Coroutines, OkHttp (MockWebServer 3 in tests), kotlinx.serialization, Jetpack Compose (Material 3), Glance, Robolectric, Python 3 (mock server).

**Spec:** `docs/superpowers/specs/2026-11-18-0009-user-token-design.md`. Read it before each task. Section numbers below (§5.x) point into it.

## Global Constraints

- Branch `0009-user-token` from `epic-widget-improvements`; merge back into the epic after review.
- Gradle runs on JDK 17: `export JAVA_HOME=/usr/lib/jvm/java-17-openjdk`.
- Default token type is `ADMIN`. Old stored settings and the old token record load unchanged (ADMIN, Admin slot). `schemaVersion` stays 1 in both records.
- The admin path (`POST /api/template`) keeps its behaviour. `HomeAssistantSourceTest` stays green with no change to its assertions.
- A token never goes into a log, an exception message, a `SyncError`, UI state or a URL. Only the `Authorization: Bearer` header carries it.
- The app never writes to Home Assistant: only `GET /api/states[/<id>]` and the existing `POST /api/template`.
- User sync: at most **4** requests open at the same time; each request has the shared client's 10 s call timeout; the sensor search (`GET /api/states`) uses a 30 s call timeout.
- `domain/` imports nothing from `android.*`.
- Every visible text goes in `res/values/strings.xml` and `res/values-uk/strings.xml` in the same commit (`NoHardcodedTextTest`).
- Code comments: use the `writing-code-comments` skill before writing them.
- Commits: `type(scope): Capitalized imperative summary` (≤50 chars, no period), header only, trailer `Co-Authored-By: <model> <noreply@anthropic.com>`.
- Never run connected tests or `adb uninstall` on the owner's phone. No instrumented run unless the owner asks; `androidTest` must compile.

## Review Focus

1. Base URL with a path (reverse proxy, `https://host/ha`) or a trailing slash: the GET must go to `/ha/api/states/<id>`, like the template path keeps `/ha/api/template` → test in Task 3.
2. A proxy page (KeenDNS, captive portal) answering 200 with HTML: the whole sync is `BadResponse`, not a crash and not an empty reading → test in Task 4.
3. HA answers 200 with JSON that has no `state` or `"state": null`: that value is missing, the sync still succeeds → test in Task 4.
4. The same id in two fields (e.g. MOSFET also listed as a temperature): one request, both fields get the value → test in Task 4.
5. A large `/api/states` (2,000 entities): the search still returns the sorted sensors, cut at 8 → test in Task 5.

- Test: create `app/src/test/kotlin/io/lumensync/habattery/data/ha/HaHttpTest.kt`; `HomeAssistantSourceTest` unchanged

**Interfaces:**
- Produces:
  ```kotlin
  internal sealed interface HaReply {
    data class Body(val text: String) : HaReply
    data class Failure(val error: SyncError) : HaReply
  }
  internal class HaHttp(client: OkHttpClient) {
    suspend fun get(connection: ConnectionSettings, path: List<String>, token: String): HaReply
    suspend fun post(connection: ConnectionSettings, path: List<String>, json: String, token: String): HaReply
    fun withCallTimeout(seconds: Long): HaHttp  // client.newBuilder().callTimeout(...): same pool
  }
  ```
  `path` = raw segments, e.g. `listOf("api", "states", id)`; each is added with `HttpUrl.Builder.addPathSegment` onto the base URL parsed from `connection.url.trim().trimEnd('/')`.
  Mapping (today's rules, moved): `UrlPolicy.INVALID` or unparsable URL → `Unreachable`; header the client refuses → `Unauthorized`; 401/403 → `Unauthorized`; other non-2xx → `HttpError(code)`; `IOException` → `Unreachable`; runs on `Dispatchers.IO`.

- Produces: `class StatesSource(client: OkHttpClient, private val clock: () -> Long = System::currentTimeMillis) : BatterySource`. In this task `listTemperatureSensors` may throw `NotImplementedError`; Task 5 fills it.

`fetch` (spec §5.4):
1. Ids = the 10 single fields + `temperatures`; blank and ids not matching `Validation`'s entity-id pattern get no request and no value; the rest are de-duplicated.
2. `coroutineScope` + `async` per id, gated by `Semaphore(4)`; `http.get(connection, listOf("api", "states", id), token)`.
3. `Body` → decode `@Serializable internal data class StateReply(val state: String? = null)` with `StoreJson`; decode failure → whole sync `BadResponse`. `Failure(HttpError(404))` → no value. Any other `Failure` → whole sync fails with it; the other calls are cancelled (first failure wins).
4. Numbers: `state?.trim()?.toDoubleOrNull()`; balancing: raw `state`.
5. Build `TemplateResponse(soc = …, totalV = …, …, temps = entities.temperatures.map { value(it) }, balancing = …)` — one `temps` entry per configured id, in order — then `toReading(clock())`; null → `BadResponse`.
