# HA Battery Widget clean rewrite — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Rewrite the app from zero as `io.lumensync.habattery`: one sync
path, a Glance widget that renders local data only, English + Ukrainian
resources, a Keystore-encrypted token and no config defaults.

**Architecture:** One `:app` module with Google's layered architecture:
`ui`, `widget`, `system` and `data` depend on a pure-Kotlin `domain`
(models, rules, ports). `AppContainer` wires everything by hand. One use
case, `SyncBattery`, serves every refresh trigger.

**Tech Stack:** Kotlin 2.3.20, AGP 9.0.1, Compose BOM 2026.03.01 +
Material 3, Glance 1.2.0, WorkManager 2.12.0, typed DataStore 1.2.1 with
kotlinx.serialization JSON, OkHttp 5, JUnit 4, kotlinx-coroutines-test,
MockWebServer 3, Robolectric, glance-appwidget-testing.

**Spec:** `docs/superpowers/specs/2026-11-14-0001-clean-rewrite-design.md`
(approved by the owner on 2026-11-14). Read it before Task 1. `§N` below
means a section of the spec.

**Branch:** `0001-clean-rewrite`, made from `develop`. The old code stays
readable with `git show develop:<path>`; use it only to match the look
(colours, spacing, sizes), never as a pattern.

## Decisions beyond the spec (made in this plan)

1. `UrlPolicy` lives in `domain/`, not `data/ha/`: `Validation` needs it and
   it is pure Kotlin.
2. Loopback (`127.0.0.0/8`, `::1`) counts as `localhost`. MockWebServer tests
   need it.
3. `BatteryOverview` (domain): one pure view model for the widget and the
   screen's preview card (DRY).
4. `format/Formatters`: one Context-based text formatter for the widget, the
   screen and the notification.
5. Stored files wrap domain models: `SettingsRecord`, `CacheRecord`,
   `TokenRecord`, each with `schemaVersion = 1`.
6. Widget error layout text: "Widget error. Open the app." A static error
   layout cannot carry a tap action.
7. The ↻ one-time work has no network constraint and is not expedited:
   fast error feedback, and no foreground info needed below API 31.
8. The worker retries `Unreachable` while `runAttemptCount < 3`; every other
   result returns `success()`, so periodic work continues.
9. After a successful save of connection, token or entities, the screen runs
   a sync.
10. `versionCode 1`, `versionName "0.1.0"`.
11. Kept from the old app: launcher icons (`mipmap-*`,
    `drawable/ic_launcher_*`), `drawable/ic_battery_full_notification.xml`,
    `drawable/preview_card_bg.xml`. Everything else is rewritten.

## Review Focus

1. HA, or a proxy login page in front of it, answers 200 with HTML: the
   result is `BadResponse` and no crash (Task 6, `htmlBody_isBadResponse`).
2. Charge outside 0–100 because of a sensor glitch (104.6, −2): the progress
   bar and time are clamped, and time is never negative (Task 2,
   `progress_clamps`, `timeRemaining_clampsCharge`).
3. A Ukrainian user types capacity `314,5`: it is parsed as 314.5 (Task 8,
   `parseDecimal_*`; Task 12, `saveCapacity_ukrainianComma`).
4. A token pasted with spaces or a newline is stored trimmed (Task 5,
   `set_trimsToken`).
5. Base URL with a trailing slash, or a fallback equal to the primary: one
   correct request to `/api/template` (Task 6, `trailingSlash_*`,
   `sameFallback_*`).

- [ ] **Step 3: Implement the models, `BatteryMath` and `FullChargeRule`**

`state`: `rounded = chargePercent.roundToInt()`; FULL if `rounded >= 100`
and (`power == null` or `power >= -20`); then UNKNOWN if power is null; then
DISCHARGING `< -20`, CHARGING `> 20`, else IDLE. `cellStats`: ignore nulls;
null when fewer than 2 values; ties pick the lowest index; delta =
`((max - min) * 1000).roundToInt()`. `timeRemaining`: null unless state is
CHARGING/DISCHARGING, current present with `|current| >= 0.5`, capacity
present; charge clamped to 0..100; hours = `soc/100 × cap / |I|` (to empty)
or `(100 − soc)/100 × cap / |I|` (to full); duration =
`(hours * 60).roundToLong().minutes`. `FullChargeRule`: FULL → notify =
`enabled && !already`, notified = `if (enabled) true else already`; otherwise
notified = `if (charge.roundToInt() <= 98) false else already`.
