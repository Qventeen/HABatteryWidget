# Value Colours Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Colour every widget value by owner-editable levels (built-in defaults, a "Custom colours" copy per value), add a direction arrow to the voltage pill and level icons to the temperature pills.

**Architecture:** A pure level model in `domain` (types, defaults, picking) replaces `WidgetLevels` / `Level`. `WidgetModel` carries a `LevelLook` (palette colour + optional icon) per value; `WidgetPalette` / `WidgetColors` map the 8 colours plus "plain" to shades. Settings store only the owner's own lists (`Settings.colorLevels`, empty by default). A new collapsible "Colours" section edits them through `MainViewModel`.

**Tech Stack:** Kotlin, kotlinx.serialization (JSON DataStore), Jetpack Glance, Jetpack Compose (Material 3), Robolectric, JUnit 4.

**Spec:** `docs/superpowers/specs/2026-11-18-0010-value-colors-design.md`. Read it before each task; §3.x below points into it.

## Global Constraints

- Branch `0010-value-colors` from `epic-widget-improvements` (after 0009 is merged into the epic if it was built first). Merge back into the epic after review.
- Gradle runs on JDK 17: `export JAVA_HOME=/usr/lib/jvm/java-17-openjdk`.
- `domain/` imports nothing from `android.*`.
- Stored data: `schemaVersion` stays 1; the new field `Settings.colorLevels` defaults to an empty map, so old files load unchanged and no migration is needed (0001 §14).
- "from X" includes X. An edge has the precision the value is shown with: SOC 0, voltage 2, current 1 (amps), delta 0 (mV), temperatures 0 decimals. Average cell compares at 3 decimals.
- At most 6 levels per value (`MAX_LEVELS = 6`).
- Colours: exactly the hex values of spec §3.4. Today's red, amber, green and grey stay unchanged.
- Level icons: Material Symbols Rounded `ac_unit`, `eco`, `local_fire_department`, `emergency_heat` (Apache-2.0); each drawable starts with a comment naming the source icon and the licence.
- Every visible text goes in `res/values/strings.xml` and `res/values-uk/strings.xml` in the same commit (`NoHardcodedTextTest`).
- Code comments: use the `writing-code-comments` skill before writing them.
- Commits: `type(scope): Capitalized imperative summary` (≤50 chars, no period), header only, trailer `Co-Authored-By: <model> <noreply@anthropic.com>`.
- No design-canvas work. The fit is checked by the owner on the phone (Task 6). No instrumented run unless the owner asks; `androidTest` must compile. Never run connected tests or `adb uninstall` on the owner's phone.
- Done gate: `./gradlew lint testDebugUnitTest assembleRelease :app:compileDebugAndroidTestKotlin`.

## Review Focus

1. A settings file written by a later app version holds a `colorLevels` key this version does not know (for example an inverter value of 0012): the file must load, the unknown key is ignored, nothing is reset → test in Task 1.
2. A current exactly on a C-rate edge: 20.0 A on 100 Ah is green, not blue (0.2 × 100 is 20.000000000000004 in floating point) → test in Task 2.
3. A current near zero: 0.1 A is idle grey, 0.15 A charging on 100 Ah is blue → test in Task 4.
4. Edges typed in Ukrainian: "52,5" and "-5" parse; a blank or repeated edge shows a field error and saves nothing → tests in Task 7.
5. A stored list edited by hand (unsorted, or the first level with an edge): the widget still picks the right level and does not crash → test in Task 2.

  | Value | Levels: from → type, name, extra |
  |---|---|
  | SOC | null → CRITICAL LOW; 20 → WARNING GETTING_LOW; 40 → NORMAL NORMAL; 100 → INFO FULL |
  | VOLTAGE | null → NORMAL NORMAL, color PLAIN |
  | CHARGE_CURRENT, DISCHARGE_CURRENT (capacity C > 0) | null → INFO LIGHT; 0.2·C → NORMAL NORMAL; 0.5·C → WARNING HIGH; 0.8·C → CRITICAL VERY_HIGH; edges rounded to 1 decimal |
  | CHARGE_CURRENT, no capacity (null or ≤ 0) | null → NORMAL NORMAL (green) |
  | DISCHARGE_CURRENT, no capacity | null → NORMAL NORMAL, color AMBER |
  | DELTA | null → INFO BALANCED; 10 → NORMAL NORMAL; 20 → WARNING HIGH; 50 → CRITICAL VERY_HIGH |
  | BATTERY_TEMPERATURE | null → CRITICAL FREEZING SNOWFLAKE; 0 → INFO COOL SNOWFLAKE; 5 → NORMAL NORMAL LEAF; 45 → WARNING WARM FLAME; 55 → CRITICAL HOT FLAME_ALERT |
  | MOSFET_TEMPERATURE | null → NORMAL NORMAL LEAF; 65 → WARNING WARM FLAME; 80 → CRITICAL HOT FLAME_ALERT |

- `copyForCustom` = `of(...)` with current edges rounded to whole amps; names stay `""` with `defaultName` set (the UI translates them).
- `pick`: the level with the greatest `from ≤ shown`; the first level in list order counts as open below (its `from` is ignored); it sorts the rest by `from` itself, so an unsorted stored list still works.
- `effective`: `customLevels(value)` when `on` and its list is not empty, else `DefaultLevels.of`.
- `perCell`: every `from` divided by `cells`.
- `worst`: highest `type.rank`; first one on a tie.
